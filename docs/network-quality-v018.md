# Monitor V0.9.18 网络质量说明

- Agent 每约 60 秒对配置的 Monitor HTTPS 服务端执行 3 次 TCP 连接探测，报告成功连接的平均耗时（ms）和 TCP 连接失败比例（%）。
- Linux、OpenWrt、Windows 若有可用的系统 `ping` 命令，还会尝试执行 3 次 ICMP Ping，解析丢包比例；没有命令、权限不足或输出不能识别时保持“未检测”，不擅自填 0%。
- ICMP 可能被路由器或机房防火墙阻断，即便 HTTPS 正常也可能显示 100% 丢包，不能仅凭此判断节点离线。
- 网络异常告警以近期有效的 TCP 探测（3 次至少失败 2 次、连续约 2 分钟）判断。节点离线告警仍以心跳超时判断，避免 ICMP 禁止导致误告警。
- 网络探测使用现有 Monitor Server 地址，不扫描公共目标，不开放任意探测地址，避免变成端口扫描工具。
- 探测运行在独立协程；主采样上报不会因单次 Ping 等待而阻塞。失败状态和有效时间均有边界。

## 在线率口径

24 小时、7 天、30 天“在线率”具体是 **服务端收到心跳的分钟覆盖率**。一分钟内至少收到一次有效心跳计为已覆盖；新节点从首次上报的分钟开始计算。少于 3 个可监测分钟显示“样本不足”。这并非第三方连续可用性检测，也不能作为 SLA 保证。

## 告警与兼容性

- 同一个节点、同一种告警最多同时存在一条未恢复记录，迁移时会合并旧版重复的活动告警。
- 原有 CPU、内存、磁盘、离线和套餐告警均保留，并继续在恢复时发送已有 Webhook。
- 旧 Agent 未上报新字段时，面板网络指标显示“— / 未检测”，不会误判为 0 延迟或 0% 丢包。
- OpenWrt WAN 接口切换期间的旧、新网卡计数不相减，以防产生虚假流量突增。

## 发布顺序

V0.9.18 基于 V0.9.17 的 OpenWrt 改动构建。先完成 V0.9.17 的主分支合并，再合并 V0.9.18，才能确保 Release 版本与依赖一致。
